# AI 广告制作 Agent

**用一句需求串起脚本、人物、关键帧、动态镜头、声音、剪辑、质检与交付。**

一个面向商业短视频生产的人机协同工作流概念：关键节点由人确认，问题镜头可局部重做，全部素材、版本与验收证据留在同一条生产链中。

## 它是什么

AI 广告制作 Agent 不是一个只负责“生成几段视频”的聊天界面，而是一套面向真实交付的制作系统设计：它读取品牌资产和制作规则，把自然语言需求拆成可执行、可审核、可迭代的任务，并在每轮修改中保留原素材、版本关系和质量证据。

这个 Demo 用一个完整案例回答三个问题：

1. 如何把模糊的广告需求转成脚本、分镜、人物锚点、镜头、声音和交付规格？
2. 如何让人始终掌握脚本、人物、关键帧、品牌和版本选择等关键决策？
3. 如何只重做出问题的局部，并让每次修改都有来源、结果和验收记录？

## 一条可控的广告视频生产链

| 阶段 | 产出 | 人工确认点 |
| --- | --- | --- |
| 01 · 需求与脚本 | 故事节奏、分镜序列、台词、声音分层、帧精确时间轴 | 脚本和交付目标 |
| 02 · 人物定妆 | 近景与全身人物锚定图，锁定身份、服装、体型和光向 | 人物一致性基准 |
| 03 · 场景与关键帧 | 逐镜关键帧与落选备选，按视觉规则完成自查 | 构图、品牌与镜头内容 |
| 04 · 动态镜头 | 以关键帧为首帧生成镜头，并检查身份漂移、产品与动作问题 | 镜头收片 |
| 05 · 声音设计 | 环境声、音效、BGM、旁白分层与响度控制 | 声音方向和旁白 |
| 06 · 帧精确合成 | 镜头、音效、旁白与品牌卡按时间轴对齐 | 剪辑节奏和成片版本 |
| 07 · 质检与交付 | 抽帧检查、规格核验、响度检查和最终验收记录 | 成片交付 |
| 08–10 · 定向迭代 | 加镜、重做问题动作、删镜提速、替换片尾、品牌贴标 | 每轮只确认发生变化的部分 |

## 核心设计原则

| 原则 | 在 Demo 中如何体现 |
| --- | --- |
| **人掌握关键决策** | 脚本、人物锚定、关键帧、加镜、剪辑与品牌版本都设有明确确认点。 |
| **局部重跑** | 取瓶方向或开盖动作有问题时，只重做对应镜头；已验收的音频与素材继续复用。 |
| **版本不覆盖** | P01–P04、贴标前后、V1/V2 审核版并存，可直接并排比较。 |
| **资产可追溯** | 脚本、人物图、关键帧、视频片段、音频、成片与质检记录集中在“产出”中。 |
| **质量有证据** | 通过人物一致性、产品完整性、抽帧、规格和响度等可核验项目完成验收。 |
| **品牌进入流程** | 品牌资产不是最后贴上去的装饰，而是脚本、视觉、自查和贴标版本的共同约束。 |

## 演示包含什么

- **10 个制作阶段**：7 个主线阶段与 3 轮定向迭代。
- **6 条历史版本记录**：从全链路验证到最终 Logo 定稿。
- **31 个项目产出**：关键帧、人物锚定、逐镜视频、音轨、审核版和最终成片。
- **3 组版本对比**：动态／固定贴标、P03／P04 节奏、贴标前／贴标后。
- **完整人机对话**：所有确认、返工原因、风险说明与验收结果按时间顺序回放。

在线打开 [AI 广告制作 Agent](https://tianming332.github.io/Tian-AI-Video-Production-Agent-V1/)，发送界面中预置的需求即可开始回放。每次继续发送，系统会推进到下一批历史步骤；你也可以随时查看产出文件、版本对比和历史项目。

## 这份 Demo 不包含什么

- 不包含实际的 Agent 后端、模型路由、任务队列或媒体生成接口。
- 不会根据你输入的新需求生成新脚本、图片、音频或视频。
- 不会上传、保存或分析你在界面中输入的内容。
- 页面中的效率数据来自该演示案例，不代表所有题材和生产环境的固定结果。

这些边界是有意保留的：此仓库用于展示产品逻辑、交互方式与项目证据，而不是公开生产系统或第三方服务配置。

## 本地查看

仓库是纯静态页面，不需要安装依赖。为保证音视频可以正常加载，建议在目录内启动本地 HTTP 服务：

```bash
python3 -m http.server 8000
```

然后访问 `http://localhost:8000`。也可以直接打开 `index.html`，但部分浏览器会限制本地文件中的媒体加载。
